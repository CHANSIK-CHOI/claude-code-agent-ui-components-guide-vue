## 접근성(a11y) 규칙

퍼블리셔가 마크업을 작성할 때 반드시 지켜야 하는 최소 기준입니다.

### 시맨틱 HTML 우선 (BLOCKING)

기능에 맞는 HTML 태그를 사용한다. `<div>`로 모든 것을 만들지 않는다.

```html
<!-- ❌ -->
<div class="button" @click="submit">저장</div>

<!-- ✅ -->
<button class="button" type="button" @click="submit">저장</button>
```

| 용도 | 올바른 태그 |
|------|------------|
| 버튼 | `<button type="button">` |
| 폼 제출 | `<button type="submit">` |
| 페이지 이동 | `<a href="...">` |
| 이미지 | `<img src="..." alt="...">` (Vite import 또는 placeholder 패턴 — 아래 "이미지 alt 텍스트" 절 참조) |
| 목록 | `<ul>` / `<ol>` + `<li>` |
| 표 | `<table>` + `<th>`, `<td>` |
| 섹션 구분 | `<header>`, `<main>`, `<footer>`, `<section>`, `<nav>` |
| 헤딩 | `<h1>` ~ `<h6>` (시맨틱 헤딩이 필요한 경우에 한함 — 팝업 마크업에선 `<span>` 기본, `rules/popups.md §6` 참조) |

### `role` 속성으로 시맨틱 태그 우회 금지 (BLOCKING)

네이티브 태그가 존재하는 경우 절대 `role` 속성으로 우회하지 않는다. `role`은 ARIA가 정의한 의미를 div/span에 "흉내내게" 하는 임시 수단일 뿐, 네이티브 태그가 자동으로 제공하는 키보드·포커스·시맨틱 트리·디폴트 동작을 모두 직접 구현해야 하므로 **항상 더 취약하고 더 장황한 마크업**이 된다.

| 금지 패턴 | 올바른 패턴 | 사유 |
|-----------|------------|------|
| `<div role="button" tabindex="0" @click="...">` | `<button type="button" @click="...">` | 키보드 Enter/Space·포커스·disabled 자동 처리 |
| `<div role="link" tabindex="0" @click="navigateTo(...)">` | `<NuxtLink to="...">` (내부 라우팅) 또는 `<a href="...">` (외부 링크) | 우클릭 새 탭 열기·미들 클릭·prefetch·SEO·키보드 Enter 자동 처리 |
| `<div role="img" aria-label="상품 이미지">` | `<img src="..." alt="상품 이미지">` | 이미지 시맨틱·alt 노출·SEO·우클릭 저장 등 자동 |
| `<div role="list">` + `<div role="listitem">` | `<ul>` + `<li>` | 스크린리더의 항목 수 안내 자동 |
| `<div role="heading" aria-level="2">` | `<h2>` | 헤딩 계층 자동 |
| `<div role="navigation">` | `<nav>` | 랜드마크 자동 |

**원칙**: *"`role`을 쓰고 싶다는 생각이 든다면 그 자리는 네이티브 태그를 써야 하는 자리"*. 본 규칙은 `/component-create` 등 모든 마크업 작성 명령에서 BLOCKER 등급으로 적용된다.

> **예외**: 네이티브 태그가 존재하지 않는 ARIA 패턴(`role="tablist"`, `role="dialog"`, `role="combobox"` 등 — Radix Vue 등 헤드리스 라이브러리가 자동 부여)은 본 규칙 대상이 아니다. 본 규칙은 "네이티브 태그가 있는데도 div/span + role로 만든 경우"에 한정된다.

### 이벤트 핸들러 — `<button>` / `<a>` 태그에만 (BLOCKING)

`click`, `keydown` 등 사용자 인터랙션 이벤트는 **`<button>` 또는 `<a>` 태그에만** 연결한다.
`<div>`, `<span>`, `<li>`, `<ul>` 등 일반 요소에 직접 이벤트를 걸지 않는다.

인터랙션이 필요한 경우 `role="button"` + `tabindex` 조합 대신 항상 `<button>` 태그를 사용한다.

| 금지 패턴 | 올바른 패턴 |
|-----------|-----------|
| `<div @click="fn">` | `<button type="button" @click="fn">` |
| `<li @click="fn">` | `<li><button type="button" @click="fn">…</button></li>` |
| `<div role="button" tabindex="0" @click="fn">` | `<button type="button" @click="fn">` |
| `<span @keydown.enter="fn">` | `<button type="button" @click="fn">` |

```vue
<!-- ❌ 금지 — li에 click 이벤트 + role="button" 조합 -->
<li
  role="button"
  tabindex="0"
  @click="selectItem(item)"
  @keydown.enter.space.prevent="selectItem(item)"
>
  <div class="card">...</div>
</li>

<!-- ✅ 올바른 패턴 — li는 컨테이너, 인터랙션은 button으로 -->
<li>
  <button type="button" class="card" @click="selectItem(item)">...</button>
</li>
```

### 버튼 / 링크 규칙

- `<button>`은 반드시 `type` 속성 명시 (`type="button"` 또는 `type="submit"`)
- 아이콘만 있는 버튼은 반드시 `aria-label` 추가

```html
<!-- ✅ 아이콘 버튼 -->
<button type="button" aria-label="닫기">
  <IconClose />
</button>
```

- `<a>` 태그는 href가 없으면 `<button>`으로 대체
- 새 탭으로 열리는 링크는 `aria-label`에 "(새 탭에서 열림)" 명시

### disabled 상태

네이티브 `<button>`은 `disabled` 속성만으로 보조기기에 비활성 상태가 자동 전달된다 — `aria-disabled` 중복 추가 금지.

```vue
<!-- ✅ 네이티브 button -->
<button type="button" :disabled="disabled" class="button">
```

```vue
<!-- ✅ 커스텀(div 등 비-button 요소): aria-disabled 필요 -->
<div role="button" :aria-disabled="disabled" :tabindex="disabled ? -1 : 0">
```

- `disabled` 상태에서는 클릭 이벤트가 발생하지 않아야 한다
- 시각적으로도 명확하게 구분 (opacity, cursor: not-allowed)

### 클릭 차단 처리 — `pointer-events: none` 사용 정책

요소 종류에 따라 차단 방식을 다르게 적용한다. 안정성을 위해 가능한 경우 **이중 차단**(속성 + 핸들러)을 권장한다.

**1) 네이티브 `disabled` 속성이 있는 요소** (`<button>`, `<input>`, `<textarea>`, `<select>`)

`pointer-events: none` 사용 금지. 다음 두 가지를 함께 적용:

| 처리 | 방법 |
|------|------|
| 1차 차단 (보조기기 알림 포함) | 네이티브 `disabled` 속성 |
| 2차 차단 (안정성) | 핸들러에서 early return |

```vue
<!-- ✅ 이중 차단 -->
<button type="button" :disabled="disabled || loading" @click="handleClick">
  <slot />
</button>
<script setup>
function handleClick(e) {
  if (disabled || loading) return  // 핸들러 early return
  emit('click', e)
}
</script>
```

**2) 네이티브 `disabled` 속성이 없는 요소** (`<a>`, `<NuxtLink>` 등)

`<a>` 태그에는 `disabled` 속성이 없어 다른 방식이 필수다. `pointer-events: none` 예외 허용. 다음 네 가지를 함께 적용:

| 처리 | 방법 |
|------|------|
| 보조기기 비활성 알림 | `aria-disabled="true"` |
| 키보드 탐색 제외 | `tabindex="-1"` |
| 마우스 클릭 차단 | `pointer-events: none` (CSS) |
| 핸들러 차단 (안정성) | 핸들러에서 early return |

```vue
<!-- ✅ <a> 태그 비활성 처리 -->
<a
  :href="disabled ? undefined : href"
  :aria-disabled="disabled || undefined"
  :tabindex="disabled ? -1 : undefined"
  :class="{ 'is-disabled': disabled }"
  @click="handleClick"
>
  <slot />
</a>
<style scoped>
.is-disabled { pointer-events: none; cursor: not-allowed; opacity: 0.5; }
</style>
```

**금지 사항**

- `<button>` 등 네이티브 `disabled`가 있는 요소에 `pointer-events: none`을 단독 사용 — 보조기기에 비활성 상태를 전달하지 못함
- `loading` 상태를 `pointer-events: none`만으로 처리 — 핸들러 차단 동시 적용

### 폼 요소 규칙

모든 입력 요소에 `<label>`을 연결한다.

```html
<!-- ✅ label for + input id 연결 -->
<label for="email">이메일</label>
<input id="email" type="email" />

<!-- ✅ 또는 label로 감싸기 -->
<label>
  이메일
  <input type="email" />
</label>

<!-- ❌ label 없는 input 금지 -->
<input type="email" placeholder="이메일만 있으면 안 됨" />
```

에러 메시지는 `aria-describedby`로 연결한다.

```html
<input id="email" aria-describedby="email-error" aria-invalid="true" />
<p id="email-error" class="input__error">올바른 이메일을 입력해주세요.</p>
```

### 이미지 alt 텍스트

```html
<!-- ✅ 의미 있는 이미지 -->
<img src="product.jpg" alt="수분크림 50ml" />

<!-- ✅ 장식용 이미지 (alt 비워두기) -->
<img src="divider.png" alt="" role="presentation" />

<!-- ❌ alt 누락 금지 -->
<img src="product.jpg" />

<!-- ❌ <div role="img"> 패턴 금지 — 위 "role 속성으로 시맨틱 태그 우회 금지" 규칙 위반 -->
<div class="..." role="img" aria-label="상품 이미지"></div>
```

> **이미지 placeholder(이미지 파일이 아직 없을 때)**도 동일하게 `<img>` 태그로 작성한다. `<div role="img">`로 자리만 잡는 패턴은 절대 금지.

**이미지 placeholder 패턴 (단일 출처)** — 이미지 파일이 아직 없어도 `<img>` 태그로 자리를 잡는다:

```vue
<template>
  <!-- ✅ 권장 — <img> 태그 + 빈 src 변수 + alt + TODO 주석 -->
  <!-- TODO: 이미지 연결 필요 — {이미지 설명, 권장 사이즈} -->
  <img class="{block}__{name}Img" :src="{name}ImgSrc" alt="{의미 있는 설명}" />
</template>

<script setup lang="ts">
  // TODO: 이미지 import 후 변수 교체 → import {name}ImgSrc from '@nd/assets/images/{filename}.png'
  const {name}ImgSrc = ''
</script>
```

```scss
.#{$b}__{name}Img {
  display: block;
  width: 100%;
  aspect-ratio: {비율}; // 예: 1 / 1, 16 / 9
  background-color: $bg-secondary; // src 비어있을 때 자리 표시 — 실제 이미지 연결되면 자연스럽게 가려짐
  object-fit: cover;
}
```

이미지 import 는 Vite 빌드 타임 처리를 위해 정적 import 만 사용한다 (동적 경로 문자열 금지):

```ts
// ✅ Vite가 빌드 타임에 처리 — 권장
import bannerSrc from '@nd/assets/images/banner-promo.png'

// ❌ 동적 경로 (Vite가 인식 못 해 빌드 시 누락 위험)
const bannerSrc = `/images/${name}.png`
```

### 포커스 / 키보드 탐색

- 커스텀 인터랙티브 요소는 키보드로 접근 가능해야 한다
- `outline: none` / `outline: 0` 단독 사용 금지 — 포커스 스타일 반드시 대체 제공

```scss
// ❌ 금지
.button:focus {
  outline: none;
}

// ✅ 대체 포커스 스타일 제공
.button:focus-visible {
  outline: none;
  box-shadow: 0 0 0 2px $color-primary;
}
```

### 색상 대비

- 텍스트와 배경의 명도 대비 **4.5:1 이상** 유지 (WCAG AA 기준)
- 색상만으로 상태를 표현하지 않는다 — 아이콘, 텍스트, 패턴 함께 사용

```html
<!-- ❌ 색상만으로 에러 표시 -->
<input class="input--error" />

<!-- ✅ 색상 + 텍스트 메시지 함께 -->
<input class="input--error" aria-invalid="true" />
<p class="input__error">필수 입력 항목입니다.</p>
```
