## 사용법

```
/git:commit
```

## 프로세스

1. 스테이지된 파일 확인 (있으면 해당 파일만 대상으로 함)
2. `git status` 및 `git diff`로 변경사항 분석
3. 여러 논리적 변경사항이 섞여있는지 확인
4. **Plan 모드로 커밋 계획 제안** (아래 "제안 포맷" 참고)
5. **사용자 승인 대기** — 승인 없이 커밋 절대 금지
6. 승인 후 제안한 대로 커밋 실행 (분할 커밋인 경우 순서대로)
7. 커밋 완료 후 push는 **사용자가 직접 실행** (아래 "Push 규칙" 참고)

## 제안 포맷 (Plan 모드)

커밋 실행 전 반드시 아래 형식으로 제안하고 승인을 받을 것:

**단일 커밋인 경우:**

```
📝 커밋 계획

타입: <type>
메시지: <type>: <subject>
대상 파일:
  - path/to/file1
  - path/to/file2

이대로 커밋할까요? 타입이나 메시지 수정이 필요하면 알려주세요.
```

**분할 커밋인 경우:**

```
📝 커밋 계획 (N개 분할 제안)

[1/N] <type>: <subject>
  이유: <왜 이 타입인지, 왜 분리하는지>
  파일:
    - path/to/file1

[2/N] <type>: <subject>
  이유: ...
  파일:
    - path/to/file2

이대로 진행할까요? 분할 방식이나 타입 수정이 필요하면 알려주세요.
```

- 사용자가 타입/메시지/분할 방식에 대해 피드백을 주면 수정된 계획을 다시 제안하고 재승인 받을 것
- 사용자가 "OK", "진행", "ㄱㄱ" 등으로 승인한 경우에만 실제 커밋 실행

## 커밋 포맷

`<type>: <subject>`

**타입:**

- `feat`: 새로운 기능
- `fix`: 버그 수정
- `hotfix`: 긴급 수정
- `docs`: 문서화
- `style`: 코드 포맷팅
- `refactor`: 코드 리팩토링
- `remove`: 코드/파일 삭제
- `typo`: 오타 수정
- `perf`: 성능 개선
- `test`: 테스트
- `build`: 빌드 시스템
- `chore`: 빌드/설정
- `ci`: CI/CD
- `deploy`: 배포
- `security`: 보안
- `accessibility`: 접근성
- `i18n`: 국제화
- `ui`: UI/UX
- `animation`: 애니메이션
- `ticket`: 티켓 관련
- `revert`: 되돌리기

**규칙:**

- 형식: `<type>: <subject>` (콜론 뒤 공백 1개)
- 타입은 반드시 소문자
- 명령형 어조 ("추가" not "추가됨")
- 첫 줄 72자 미만
- 원자적 커밋 (단일 목적)
- 관련 없는 변경사항 분할
- 커밋 전 `git status`로 변경사항 최종 확인
- 빈 커밋 금지

**금지:**

- ❌ 사용자 승인 없이 커밋 실행
- ❌ `커밋 메시지` — 타입 없음
- ❌ `update: 파일 수정` — 허용되지 않은 타입
- ❌ `feat` — subject 없음
- ❌ `FEAT: 대문자 사용` — 소문자만 허용

## 분할 기준

다른 관심사 | 혼합된 타입 | 파일 패턴 | 큰 변경사항

## 참고사항

- 스테이지된 파일이 있으면 해당 파일만 커밋
- 분할 제안을 위한 diff 분석 필수
- **커밋에 Claude 서명 절대 추가하지 않음**
- 사용자가 제안한 타입과 AI가 판단한 타입이 다를 수 있으므로 반드시 승인 절차 거칠 것

## ⚠️ 커밋 실행 조건 (최우선 규칙)

- **커밋은 반드시 사용자가 `/git:commit` 명령을 직접 입력했을 때만 실행한다**
- 작업 완료 후 자동으로 커밋하거나, 대화 흐름 중 임의로 커밋하는 것은 절대 금지
- `/git:commit` 이외의 문맥에서 "커밋할까요?" 등 커밋을 제안하는 것도 금지
- 사용자가 "네", "OK" 등으로 작업에 동의해도 그것은 커밋 승인이 아님
- 커밋 승인은 오직 `/git:commit` 스킬 실행 후 계획 제안에 대한 명시적 응답만 인정

## Push 규칙

- 이 환경에선 보안 정책상 `git push`가 막혀 있다 (`.claude/settings.json`의 deny에 `Bash(git push *)` 등록)
- 에이전트는 push를 시도하지 않는다
- 커밋 완료 후 안내만 출력:
  > "푸시는 사용자가 직접 `git push origin <현재 브랜치>`로 실행해주세요."
